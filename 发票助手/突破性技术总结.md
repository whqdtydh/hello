## 突破 1：WebView2 替换 QtWebEngine——渲染引擎架构级轻量化

**时间**：2026-08-19
**突破点**：打包产物 500MB 中 QtWebEngine 占 265MB（Qt6WebEngineCore.dll 195MB 为硬成本）。在不改 UI、不动调用方的前提下，整体替换为 WebView2 系统内核，体积预期 500 → 250MB（减半），且用户机器零安装负担（Win10/11 内置 Runtime）。

**技术方案/原理**：
1. **嵌入**：pythonnet + WebView2 SDK 控件，`QWindow.fromWinId(HWND)` + `createWindowContainer` 嵌入 QWidget 布局，PySide6 UI 零改动。
2. **自动化通道**：不开 WebView2 的 WebMessage（受限），改走 CDP（`--remote-debugging-port` + WebSocket）。CDP 是持久连接，JS 调用毫秒级往返，比 QtWebEngine 的 runJavaScript（跨进程+QVariant 序列化）快一个量级。
3. **绕开 WebView2 CDP 子集限制**（关键结论）：
   - `Page.navigate` 是**假导航**（只更新 target 元数据，页面不动）→ 改用原生 `CoreWebView2.Navigate()`
   - `Page.addScriptToEvaluateOnNewDocument` **不生效** → 改用原生 `AddScriptToExecuteOnDocumentCreatedAsync`
4. **排障根因**：CDP 单调试器限制——外部 probe 连入会踢断主程序连接，表现"下载不了邮件"。解法：CDP 客户端断线自动重连 + 页面脚本源重放。
5. **性能副产物**：CDP 直连使勾选→下载链路耗时明显缩短（无线程转发、无类型转换、DocumentCreated 更早注入 tracker）。

**验证结果**：
- P0（pywebview+CDP）：HttpOnly cookie 全量可读（发现新版 QQ 邮箱用 xm_skey 系列）、JS 注入、Network 抓 XHR 26 个——三项能力全过
- P0'（pythonnet 嵌入）：HWND 嵌入 + CDP 9333 + 页面加载 + 标题回读全过
- 105 测试全程通过；登录态、勾选读取、下载链路实测正常

**后续意义**：
- 结论可复用：**"QtWidgets UI + 原生 HWND 浏览器控件 + CDP 自动化"是体积敏感型桌面应用的通用路径**，可推广到任何需内嵌网页的 PySide6/PyQt 项目
- WebView2 的 CDP 坑位（假导航/addScript 失效/单调试器/握手 403）形成即查手册，下次直接避开
- 用户机器无需装额外运行时（系统内置），发布零部署成本

## 突破 2：OCR 引擎代码自有化——第三方依赖收编为项目资产

**时间**：2026-08-19
**突破点**：rapidocr_onnxruntime 从 site-packages 整体收编为 `app/engine/ocr_light/`，OCR 逻辑（源码+模型+配置）全部变为项目可控代码，保留 Apache-2.0 合规，识别精度零损失。

**技术方案/原理**：
1. 全包拷贝（含 models 15.6MB），3 处硬编码绝对导入改相对导入（`rapidocr_onnxruntime.utils` → `..utils`）
2. 模型路径基于 `Path(__file__).parent` 自动解析，移动即用
3. 收编后 OCR 逻辑可自由裁剪（如后续换更小模型、砍 cv2 预处理），不受第三方包版本漂移影响
4. 扫描件 PDF 降级链路验证：无文本层 PDF → OCR → 金额/乘车日期提取成功

**验证结果**：OCR 冒烟识别正常；扫描件 PDF 全链路（金额 87.0、铁路日期 2026-08-06）提取成功；105 测试通过。

**后续意义**：第三方包收编方法论成型——**包名适配（相对导入）+ 资产内嵌（模型随包）+ 合规保留（LICENSE）+ 全链路验证**，适用于任何"关键依赖自有化"需求。
